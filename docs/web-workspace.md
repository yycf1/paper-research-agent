# 电脑端研究工作区

四个主入口对应明确流程：文献库负责整理与选择，发现论文负责在线搜索和候选入库，研究助手负责带范围的问答/比较与 Agent，任务记录负责结果、进度和待确认操作。阅读页独立使用可用宽度，库内筛选与阅读状态各自保留。浏览器返回和旧 `?paper=`、`?tab=chat` 链接继续可用。

研究助手使用统一研究对话：左侧始终是历史，中间是消息与证据，底部共用输入框；提问、比较论文和执行操作通过本次操作选项选择。没有独立的单次/连续问答页面。论文范围与比较结果持久化，操作记录关联到会话；切换历史不关闭正在执行任务的连接。示例、跨页转交、操作选项都只预填，必须提交才执行。详见 [统一研究对话](unified-research-workspace.md)。

文献库中的信息记录可作为待读清单，不要求已经下载全文。“仅文献信息”说明只保存标题、作者、摘要等；其余阶段依次为“全文已保存、文本已提取、报告已生成、已建索引”，下载异常专门标为“全文下载失败”。解析、分析和索引错误仍显示在相应记录旁，不混为下载失败。阶段数量为全库统计，分组与搜索可继续筛选；“已建索引”也不替代详情页的当前版本就绪检查。

“全文文件”使用 `has_local_file` 检查记录的本地路径，而 `has_pdf` 保留原 API 的来源链接含义。文件缺失时显示“未保存”，来源提供链接时另外提示“有来源链接”，不再显示下载成功勾号。发现页默认“保存并下载全文”，另提供“仅保存信息”；后台逐篇返回文件是否取得，不用保存成功代替下载成功。

批量删除复用逐篇删除接口，确认框列出真实范围；未确认时不发请求，执行时显示进度，失败项保留勾选和原因，未选中记录不受影响。删除记录与移出分组分开；本轮没有对个人文献实际执行删除，浏览器删除场景均为原创离线响应。

问答与比较在发送前展示论文范围，结果记录实际使用范围；最多六篇，比较至少两篇。来源可展开并复制；引用结构检查通过仍提示语义支持待核对。论文详情依据 `index_state` 提供本文问答，未索引或过期时保留阅读内容与下一步提示。处理后刷新字段证据，操作错误显示在当前内容旁。

基础风格为浅色工作台、单一主色、独立状态徽标和统一按钮；已有深色选择保留。本轮按用户要求仅对电脑端做最终适配与验收，检查 1440×1000 和 1280×900。

普通处理任务保存到本地账本，Agent 历史通过 JSONL 回读。界面区别中断、等待确认与已完成；历史回读不会自动续跑。

验证分两层：

- `uv run python scripts/verify_local_contracts.py`：真实临时 SQLite/Chroma、原创文本、手写向量、脚本化答案；检查实际 API、范围、引用状态和预打包资源，无线上模型调用。测试资料写到忽略的 `data/local-contract-check`。
- `scripts/verify-web.cjs`：电脑端浏览器交互，所有 API 使用原创合成响应；检查勾选范围、筛选、比较、问答、切页结果、任务确认、局部错误、导入刷新和返回深链。可选安装 Playwright 与浏览器后先运行 `npm --prefix web run preview -- --host 127.0.0.1 --port 18809`，再执行 `node scripts/verify-web.cjs`；用 `PLAYWRIGHT_MODULE`、`PLAYWRIGHT_BROWSER_PATH`、`WEB_QA_URL`、`WEB_QA_OUTPUT` 指定本地环境。

浏览器截图是交互验收示例，不是实际模型生成质量或人工语义评测。具体检查见 [JSON 记录](web-workspace-validation.json)。
