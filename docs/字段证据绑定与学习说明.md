# 字段证据绑定与项目学习

本轮完成研究目标、数据集、评价指标三个字段的证据绑定基础。论文详情新增“字段依据”页签，跨论文比较的工具步骤新增逐字段表格，并将依据保存进任务轨迹。读取现有本地抽取和索引即可使用，不增加模型调用。

## 为什么要改

原比较工具分别返回 `extracted_facts` 和按主题检索的片段。例如抽取值写 Dice=0.99，而片段写 Dice=0.91、Accuracy=0.99，编号即使完全合法，也不能证明抽取正确。新实现把值、论文、索引版本、片段、摘录位置放在同一条记录内，分别标记引用状态与语义支持状态。

| 检查 | 本轮如何处理 | 能说明什么 |
| --- | --- | --- |
| 字段类型 | 保留 raw_value，生成 normalized_value；格式不符标 unknown | 当前抽取是否可用于展示；不代表论文没报告 |
| 引用定位 | 校验论文、chunk_id、索引版本、文本摘要、章节、页码、字符区间和逐字摘录 | 片段存在且定位正确 |
| 候选依据 | 在本文全部已索引块中用 BM25 查找；数据集名称/指标数字作保守匹配 | 提供需要核对的候选，默认 unverified |
| 语义支持 | 仅沿用与当前事实摘要完全一致的显式人工复核记录 | 一条本地声明的复核结论；不提供身份认证 |
| 数值比较 | 输出 ranking_allowed=false，界面和模型提示说明条件不足 | 不应据裸值排名；未实现自动可比性判定或对模型回答的硬拦截 |

`valid` 与 `supported` 是两条不同的轴。候选中同时出现指标名和数值，也可能对应另一模型、另一行表格或另一任务。本轮没有自动语义证明，没有用模型自评代替人工，也没有为真实数据填写“人工支持”。

## 如何查看与复跑

按原方式启动项目，打开已有论文详情，点击“字段依据”，展开“查看依据”即可看到章节、可用页码和原始摘录。Agent 运行 `compare_papers` 后，同类表格会显示在工具步骤内，轨迹回读保留这份数据。旧轨迹没有 comparison 字段时保持原展示。

以下命令在项目根目录的 PowerShell 执行，仅读取现有数据：

```powershell
& .\.venv\Scripts\python.exe scripts/inspect_field_evidence.py `
  --paper-id '填写自己库中的论文ID' `
  --paper-id '填写自己库中的论文ID' `
  --paper-id '填写自己库中的论文ID' `
  --output data/evidence-eval/field-evidence-rerun.json
```

输出 JSON 与同名 Markdown；已有报告需要换路径或显式 `--overwrite`。只读接口为 `GET /api/papers/{完整论文ID}/facts`，不存在的论文返回 404。没有抽取或索引时返回未知/缺少候选，不猜值。

历史说明见 [field_evidence_validation.md](field_evidence_validation.md)：三篇论文，预算内展示 15 项事实，10 项引用 valid、5 项 missing，15 项均 unverified。省略项单独计数。该数字不是准确率、完整召回率或整体问答效果；没有进行独立人工/PDF复核，原始抽取也可能不正确。

## 版本与人工复核

证据版本基于本文已索引块的 ID、文本、章节与页码；不是原 PDF 文件版本。引用区间使用 Python 字符下标，摘录必须逐字匹配。事实摘要还覆盖原始值、规范化值与实际引用集。原文、事实、候选依据或预算裁剪使引用集改变后，旧复核不会被迁移成新结论。索引读取顺序改变时，候选排序保持确定性。

需要真实人工核对时，可在该论文 `data/knowledge/<安全目录名>/fact_reviews.json` 保存以下结构，摘要必须从当前接口/报告读取，不能自行编造：

```json
{
  "reviews": [
    {
      "claim_sha256": "替换为当前事实的完整摘要",
      "reviewer": "实际复核者",
      "review_kind": "human",
      "status": "supported",
      "note": "实际核对过的结论及限制"
    }
  ]
}
```

允许的复核结果为 supported、unsupported、conflict、not_applicable。`supported` 还要求存在有效引用及有效字段值。重复摘要或格式错误会使本次复核文件不可用；版本不匹配记录为 unmatched_reviews。这里是本地声明式记录，不是审核系统。助手生成的匹配与阅读结果不能写成真实人工复核。

## 验收与限制

最终完整 Python 回归 **290 passed / 119.15 秒**；本轮相关 Python 文件通过 Ruff E4/E7/E9/F/I 检查。前端生产构建通过，lint 退出码为 0，仍有四条既有 React 警告；Python 仍有一条既有 Starlette/anyio 弃用提示。本轮没有收费模型调用，没有据此声称线上回答质量提升。

新增行为回归覆盖错论文、失效块、错页码/章节、伪造摘录、过期版本、字段缺失/错误类型、数字边界、句号、原文不支持/冲突、陈旧复核、索引读取顺序、预算裁剪、六篇论文输出预算，以及模型上下文/事件/轨迹保留。测试中的 human 记录仅为测试夹具，不用于证明真实论文正确。

页面联调发现首次并发访问 Chroma 时，其共享系统可能在原生 bindings 初始化完成前被另一请求取得。已在 VectorStore 的客户端初始化处加进程内互斥，检索操作不持有该锁；增加实际 Chroma 的受控重叠启动回归。该修复不声称提供跨进程事务或索引读写快照隔离。

界面验收使用 Edge，覆盖 1440px 桌面和 390px 手机：真实本地详情 API、展开摘录、未复核状态、三篇比较表及表内横向滚动。比较页面回放本地字段快照，明确为界面夹具，没有执行真实模型比较。记录见 [界面验收数据](field_evidence_ui_validation.json)，当前公开截图使用原创示例，见 [工作台](images/workspace-comparison-desktop.png)。同时修正了窄屏顶栏和详情布局。

仍有明确限制：候选使用词法规则，可能漏掉缩写、翻译和表格关系；单字段最多八条，单项与总输出都有预算，省略有标记。单位不自动转换，任务/划分/基线不会从常识补齐。未解决原抽取输入前 36,000 字符截断；这一项是下个工作包。

## 根据这次改动学习

先看产物，再沿代码追踪。每次只用一条数据，不要求重写整个项目，也不把看懂示范视作已独立掌握。

| 顺序 | 项目问题 | 直接阅读位置 | 学习完成的检查标准 |
| --- | --- | --- | --- |
| 1 | 抽取值从哪里来，为什么可能错？ | 快照中 DrugPred 的 Accuracy 行 → `services/facts.py` | 能区分原始抽取、当前候选、真实原文支持；知道 missing 不等于论文未报告 |
| 2 | 如何把一条事实绑定回片段？ | `extraction/evidence.py` 的 EvidenceReference、bind_fact、validate_reference | 能从一条事实追到 paper_id、chunk_id、quote；解释页码对与结论对为何不同 |
| 3 | 为什么旧复核不能直接复用？ | 同文件 claim_sha256 与预算处理；`tests/test_field_evidence.py` | 能指出事实、文本或引用集改变后失效的原因；允许借助 AI 运行一个临时测试，不改真实论文数据 |
| 4 | 表格怎么从工具结果到页面？ | `agent/executor.py` → `agent/loop.py` → `web/src/components/FieldEvidence.tsx` | 能讲清宿主执行工具、结果回填模型、事件/轨迹保存、前端展示这四步 |
| 5 | 为什么单测通过，实际页面仍会失败？ | `rag/vectorstore.py`、`tests/test_vectorstore_startup.py` | 能解释两个首次请求如何读到半初始化对象，以及初始化互斥的作用和范围 |

最小学习任务留在项目内：先选一个“引用 valid / 支持 unverified”的真实字段，展开原文并检查数值究竟属于谁；再运行对应测试看错误引用如何被拒绝。是否掌握，之后依据你实际解释、小范围改动与排错评估；现在继续优先完善项目，不进行口头测验。
