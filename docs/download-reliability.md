# 下载失败诊断与验收

2026-10-14 对个人运行库只读核对：333 条记录中，165 条没有候选全文链接，168 条带候选链接，15 条存在本地文件。308 条处于题录阶段，不等于 308 次下载失败；批处理默认下载预算为 10，不会下载全部检索记录。10 条下载失败状态中，9 条有非空错误：6 条 HTTP 403、2 条连接重置、1 条响应为 HTML；另 1 条无错误详情，不能归类。

此前下载函数只有四项模拟响应测试，覆盖候选顺序与简单落地页回退，没有验证真实来源可下载率；前端离线交互通过也不能代替下载验收。已下载的个别文件不能证明来源覆盖充分。

## 已复现的原因

- ACM 与 MDPI 样本返回 403 和访问挑战页面；403 证明来源拒绝请求，不能单据此区分登录、反爬或付费限制。程序不解验证码或绕过访问限制。
- DOI 样本实际跳转到 HTML 页面，无 `citation_pdf_url`，不是 PDF 文件。OpenAlex 的 `oa_url` 是全文位置，可能是落地页。[官方字段说明](https://help.openalex.org/data/works/open-access/)
- 两篇失败论文的 OpenAlex `locations` 包含 arXiv 开放副本，旧程序只保留出版社/首选地址，漏掉了其他副本。[官方位置说明](https://help.openalex.org/data/locations/)
- 原先连接重置的 arXiv 地址当前可以返回 PDF；完整文件下载和 ACL 样本又发生暂时中断，有限重试后成功。网络状态随时间变化，不能保证以后每次成功。

## 本轮修复

新检索保留其他开放副本，优先尝试直接 PDF 地址。旧 OpenAlex 记录候选用尽后，按同一 Work ID 查询一次最新位置；不自动改写个人账本，不调用模型。落地页支持相对地址、HTML 实体与最终跳转 URL。

单篇最多 12 次候选/重试 HTTP 请求，另允许一次元数据查询；连接异常、短时限流与部分 5xx 最多重试一次，403/404 不重复撞同一地址。读取超时为 30 秒，文件上限为 100 MiB；这些是请求/字节预算，不是整项任务的绝对耗时上限。

下载必须具备 PDF 签名，并由 PyMuPDF 打开、检查页面与密码状态，再原子替换目标文件。HTML 不能凭 `Content-Type: application/pdf` 通过；中断或校验失败清理本次临时文件，并保留旧文件。

开放副本可能是预印本、接受稿或正式发表版本。当前未自动证明它与出版社版本的内容相同，比较实验数字时仍需核对具体文件版本。

## 真实验收与复跑

四篇有限样本全部完成真实下载与 PDF 解析，包括两个“原地址 403 → 同 Work 开放副本”场景；页数分别为 25、12、26、29，第一页面均可提取文本。见 [下载验收 JSON](download-live-validation.json)。文件存于隔离验证目录，未处理个人文献，未调用模型；公开仓库只保存结果，不包含论文 PDF。四篇样本不能代表全库成功率。

可选显式联网复跑：

```bash
uv run python scripts/verify_download_live.py --live
```

该脚本只下载内置的四个公开候选，写入忽略的 `data/download-live/<随机目录>`，不打开个人账本；网络失败会记录原因并以非零退出。离线回归：`uv run pytest tests/test_download.py tests/test_sources_parse.py -q`。CI 继续使用离线测试，不把临时源站故障当成代码回归。

无开放链接或来源持续拒绝时，仍可能需要用户通过浏览器获取自己有权访问的文件，再导入。欧洲 PMC 批量内容应使用其官方数据接口或批量下载渠道，不能将网站页面无节制抓取作为下载保障。[官方说明](https://europepmc.org/help)
