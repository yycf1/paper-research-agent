# M13 开发笔记 · 分组自主权与高级检索

真实使用反馈驱动的里程碑，两件事：**分组从「被动标记」升级为「可管理的对象」**；
**检索条件从「关键词+年份」对齐到文献检索网站的基本盘**。

## 1. 分组自主权

**反馈**：用户找不到主动创建分组的入口，也不能把已有论文移进/移出分组——M10 的
标签只能在入库那一刻被动产生（检索词/上传标记），「先建组、后归类」不成立。

- **数据层**：新增 `groups` 表（name, created_at），标签不再是 papers.tag 的派生。
  老库迁移幂等登记已有标签；入库打标与 `set_tag` 都自动登记；`groups()` 用
  UNION 把 groups 表与论文实际标签并集输出，计数实时查询（延续 M10「不冗余存储」）。
- **API**：`POST /api/tags`（建空组，409 冲突）、`PATCH /api/tags/{name}`（重命名，
  论文标签同步 UPDATE）、`DELETE /api/tags/{name}`（删组留论文，全组回未分组）、
  `PATCH /api/papers/{sid}`（单篇归类/清除）、`POST /api/papers/batch-tag`（批量，
  missing 原样返回）。顺手把三处重复的 sid 片段解析收编为 `_resolve_sid`。
- **CLI**：`pa tag <ids...> --set <组名> | --clear`。
- **Web**：分组行加「＋ 新建分组」（行内输入）；分组 chip 悬停浮现 ✎/✕；
  列表多选（表头全选）→ 批量操作栏「移动到分组（含新建）/ 移出分组」；
  详情页元信息行改为下拉：未分组 / 各分组 / ＋ 新建分组。

**验收抓到的真 bug**：详情页下拉把「当前分组」从选项里过滤掉（只想显示“可去的
地方”），导致 select 的 value 匹配不到任何 option，回落显示成「未分组」——数据
是好的，纯展示层问题。教训：**受控 select 的 value 必须在选项集合里存在**，
“隐藏当前项”这类小聪明在表单组件上是反向优化。

## 2. 高级检索

**反馈**：检索条件只有年份，其余全靠关键词。对齐通用文献检索能力：

- **条件集**：`field`（all/title/abstract 关键词匹配范围）、`author`、`sort`
  （relevance/citations/newest）、`min_citations`、`oa_only`、`year_from/year_to`。
- **各源映射**：OpenAlex 用 `filter=title.search/abstract.search/raw_author_name.search`
  （自由文本里的 `,`/`:` 是 filter 语法保留字符，必须清掉）+ `sort`；
  EuropePMC 用官方查询语法 `TITLE:"…"`/`AUTH:"…"`/`OPEN_ACCESS:Y` + `sort=CITED desc`；
  arXiv 映射 `ti:/abs:/au:` + `sortBy=submittedDate`。
- **统一语义靠后过滤**：`min_citations`（引用未知按 0）与 `oa_only`（以 pdf_urls
  非空为准——「OA」≠「拿得到 PDF」，用户要的是后者）在服务层对所有源统一执行，
  不依赖单源能力；剔除数量进 notes 可见。构造函数全部提为纯函数（build_params /
  build_query / build_search_query），离线可测。
- **一处退化要明说**：OpenAlex 的 relevance_score 只在有 search 参数时存在，
  标题/摘要限定下「相关度」排序退化为按引用数——确定性且通常更接近用户预期。
- **入口**：API SearchRequest 新字段（pydantic pattern 校验枚举）、CLI
  `pa search --in/--author/--sort/--min-citations/--oa/--year-to`、Web「⚙ 高级筛选」
  折叠面板（默认收起，快路径保持简单）。
