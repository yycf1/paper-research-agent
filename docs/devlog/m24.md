# M24 开发笔记 · 复现工作区可视化

M19 造出了复现执行器，但产物全埋在文件系统里：`data/repro/<id>/workspace`
下的代码、每次执行的输出，浏览器里看不到——旗舰功能的"听说有"问题。M24
把它搬进详情页「复现」页签：方案 + 工作区文件（点击看代码）+ 运行记录
（exit 码徽章 + 可展开输出）。

## 1. 运行记录：此前根本不存在，先让它存在

工作区文件一直都在，但**运行输出是易失的**——run_code 的 stdout/stderr
截断后只回填给模型，进程结束即消失，轨迹里也只剩一句话摘要。可视化的
前提是先持久化：

- `_tool_run_code` 的真实执行（成功/非零/超时）追加写
  `data/repro/<id>/runs.jsonl`：时间、文件名、exit_code、timed_out、
  耗时、输出（各截 3000 字符）；
- **被确认门拒绝的执行不记录**——没有发生的事不产生档案，这条边界让
  runs.jsonl 成为可信的"实际执行过什么"审计源；
- 这是自 M23"不造第二份存储"原则的一次有意识破例：运行输出此前不存在
  于任何存储里，先让它存在才谈得上回读。

## 2. 两个只读端点，白名单与执行器同一套

- `GET /papers/{id}/repro`：方案 + 工作区文件列表（新→旧）+ 运行记录
  （新→旧），一条请求带齐详情页所需；
- `GET /papers/{id}/repro/file?name=`：查看文件内容。安全约束复用
  `_code_file` 的同一套判定——纯文件名（拒路径穿越）+ 扩展名白名单
  （.py/.md/.txt/.json/.log）+ 200KB 截断。读侧白名单比写侧宽（允许
  md/txt/log）：工作区之外没有敏感文件可读的前提是名字先过 pure-name
  这道闸，扩展名只是防误操作。

## 3. 详情页：「复现方案」页签升级为「复现」

页签改名并扩容：方案 Markdown 在上，工作区文件 chips（点击懒加载代码
盒）与运行记录（`<details>` 原生折叠展开输出）在下；页签出现条件放宽为
"有方案**或**有工作区产物"——方案被删但代码还在时入口不消失。

顺手修了一个 M16 遗留文案 bug：确认门标题硬编码「请求入库 N 篇论文」，
但 M19 起 run_code 也走同一确认插座——验收时真实任务弹出"请求入库 1 篇
论文"而条目是「运行代码 run_proto2.py」。现按首条内容区分「请求运行代码
/ 请求入库」，按钮文案同步。

## 4. 验证

- 测试：`test_api_repro.py` 5 用例（概览/文件查看与白名单/论文缺失 404/
  空工作区）+ `test_agent_repro.py` 补三处运行档案断言（成功/超时入档、
  拒绝不入档）；全量 211 通过；
- 真机闭环：提交 Agent 任务直接运行 M19 留下的 `run_proto2.py` → 确认门
  （顺便暴露并修复文案 bug）→ exit 0、20.0s → 详情页运行记录出现
  「exit 0 · run_proto2.py · 10/01 19:37 · 20.0s」，展开可见 Evolution
  Strategies 训练输出——复现证据链首次全程浏览器可见。

## 5. 面试视角

- **审计边界**：只记录真实发生的事（拒绝不留痕）——审计日志的可信度
  来自"没有虚假条目"而不是"条目多"；
- **读写同规**：文件读取端点与写入工具共用同一套文件名判定，避免
  "写侧有白名单、读侧裸奔"的常见漏洞形态（路径穿越多在读接口上发生）。
