# M28 开发笔记 · Agent 长任务上下文管理：滑动窗口压缩

P4 立项时的问题是"长会话顶爆上下文窗口"。动手前先做了一轮全链路审计，
结论修正了预期：**chat 链路早已有界，真正的失控点在 agent loop 内部**。

## 1. 审计：上下文消费点逐个过

- Web chat（`api_chat`）：history 取 `[-3:]` 相邻 (user, assistant) 对，
  只供问答链指代消解；
- 问答链（`qa.py`）：`MAX_HISTORY_TURNS = 3` 再截一次；
- 输入端：`ChatRequest` 限 2000 字符；单条 tool 消息 `llm.tool_message`
  限 4000 字符；
- 结论：chat 侧三重有界，无需动。

Agent 循环（`loop.py`）则是标准的"重放成本"问题：function-calling 循环
每一步都要把**全部历史**重放给模型——第 N 步的 prompt 包含前 N-1 步的
assistant 调用声明与工具全量结果。工具结果不小：run_code 的 stdout/stderr
各 3000 字符、read_repro_plan 3500 字符、search 候选列表。max_steps=8 时
prompt 随步数线性膨胀，累计计费接近平方级。token_budget（M15）只能
**熔断**——超了就停，救不了已经花掉的钱。

## 2. 协议约束：为什么不能像普通对话那样"截断历史"

function-calling 有个硬规则：带 `tool_calls` 的 assistant 消息必须与
后续 `role=tool` 消息按 `tool_call_id` 一一配对，从中间删掉任何一侧都会
被 API 拒绝。所以普通对话的"丢掉前 K 轮"在这里不成立，压缩只能**改写
老 tool 消息的内容**（角色与 id 不动，配对关系完好）。

## 3. 实现：滑动窗口 + 摘要桩

- `agent.context_keep_steps`（默认 4，0 = 关闭回归旧行为）：最近 N 步的
  工具结果原样保留，滑出窗口的压成摘要桩；
- 记账：`step_spans` 记录每步 tool 消息在 messages 里的下标（消息只追加
  不删除，下标稳定；同一步并行多个 tool_calls 属同一 span，一起出窗）；
  `_compact_context` 维护已压缩水位线，幂等，每步末尾调用；
- 桩的内容：`status`/`error` 保留（短且是推进线索），`data` 换成
  `_summarize_result` 的一句话摘要（复用事件流已有的摘要函数）+ 一句
  "信息已在此前的推理中消化，继续推进任务即可"；被 4000 字符截断过的
  旧内容解析失败时给通用桩；
- 窗口大小 4 的依据：M19 复现自纠错循环（读 stderr → 修 → 重跑）通常
  连续 2~3 步，检索→入库通常相邻 1~2 步——4 步窗口覆盖所有"后步依赖
  前步结果"的真实模式；更早的结果模型要么已消化进推理，要么值得重新
  调用工具取新数据（重复护栏仍在兜底）。

与 token_budget 的分工：预算按**累计用量**在下一轮前拦截（billing 视角、
硬闸），压缩降低**每轮 prompt** 的线性增长（prompt 视角、省算）——一个
管兜底，一个管日常。

## 4. 测试与验证

- 新增 5 用例：窗口语义（6 步 keep=4 → 最早 2 步出窗成桩、窗口内原样、
  配对结构逐条断言）、并行 tool_calls 同 span 一起出窗、失败结果出窗
  保留 status/error、keep=0 关闭基线、cfg 键生效；
- 全量 227 用例通过（222 + 5）；
- 浏览器回归：真实发起"库状态 + 方向推荐"任务，2 步完成（6411 tokens），
  时间线与总结渲染正常——新代码下 agent 链路端到端无损。

## 5. 面试知识点

- **function-calling 循环的成本模型**：第 N 步 prompt 含全部历史，累计
  计费 O(N²)；上下文管理不是可选项而是循环 Agent 的必修课；
- **压缩策略谱系**：截断（会破坏配对，不可用）→ 滑动窗口（保留近期、
  概括远期，本文）→ 递归摘要（老步骤让 LLM 总结成一段，成本高但窗口
  可以更小）→ 外置记忆（老结果落盘、按需检索回来）；M28 选滑动窗口，
  因为窗口内依赖模式明确且实现确定性可测；
- **熔断 vs 压缩的分工**：预算闸保护"最坏情况的钱"，窗口压缩优化
  "每一轮的账单"——护栏和优化经常被混为一谈，其实作用在不同变量上。
