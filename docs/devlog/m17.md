# M17 开发笔记 · 设置中心与文献库 UI 重构

用户试用反馈两件事：文献库页面信息堆得乱、不美观；没有地方配置模型平台
与 API Key——换 Key 要手工编辑 `.env`，对「给人用的工具」不成立。本里程碑
两线并修：**运行时设置中心**（后端配置分层 + 前端弹窗）与**文献库界面重构**
（信息架构重排 + 全局视觉打磨）。

## 1. 配置分层：为什么是覆盖层而不是改 config.yaml

设置页要写 Key，第一反应是「程序改写 config.yaml 的 llm 节」——否决：
config.yaml 是手工维护、带注释、进 git 的文件，程序化覆写要么丢注释要么
需要 YAML 保序改写库，得不偿失。采用三层优先级：

```
config.yaml（代码默认，进 git）
  <  .env（本地密钥，gitignore）
  <  data/settings.json（Web 设置页写入的运行时覆盖，gitignore）
```

- `load_config()` 每次请求都会执行（服务层本来就按请求取配置），把
  settings.json 的**非空字段**并入 llm 节——保存即生效，CLI 与 Web 共用
  同一条生效链路，无需重启；
- `resolve_endpoint()` 增加 `runtime_api_key` 优先级：Web Key > env 变量。
  该键只会在 llm 节出现，embedding 节不受影响；
- 文件损坏/缺失一律静默回退 config.yaml（`load_runtime_settings` 吞掉
  JSONDecodeError）——设置层坏了不能阻断启动。

## 2. 设置 API 三件套与密钥卫生

- `GET /api/settings`：返回生效端点 + **脱敏 Key**（`5338****Vm2C`，首 4
  尾 4）。密钥一旦明文回显就会进日志、截图、浏览器缓存——界面只需让用户
  确认「配过了」，不需要看见它；
- `PUT /api/settings`：api_key 为 None/空串表示**保持已存 Key**（表单回填
  场景不会误清空），只有显式输入新值才覆盖；
- `POST /api/settings/test`：测试连接。关键决策：**不走 `_complete` 的
  限流重试核心**——那条路径 4 次退避要等 70 秒，交互式检测不可接受。独立
  `test_endpoint()`：单次请求、20s 超时、`max_retries=0`、max_tokens=8，
  任何异常转可读文案。表单值优先于已存值（允许未保存先试）。

前端：顶栏齿轮按钮（未配 Key 时亮黄色提醒点，App 挂载时查一次 settings）；
设置弹窗内置厂商预设（智谱/DeepSeek/Moonshot/通义/OpenAI，点击填
base_url + 推荐模型），当前 base_url 命中预设时自动点亮对应 chip；
Esc 关闭；保存后提示「立即生效，无需重启」。

## 3. 文献库重构：信息架构先于美化

原来混乱的根源不是缺样式，是**四条平铺 toolbar 把六个不相关的控件堆在一
列**：主题检索、来源选择、高级筛选、库内筛选、状态过滤、分组管理彼此交织。
重排为三个功能区：

1. **检索区**（lib-head）：主题检索主输入 + 检索 + 上传；次行来源 chips +
   高级筛选折叠按钮；展开后是带字段标签的网格（作者/匹配字段/排序/最低被
   引/年份区间/仅全文），替代原来的无标签 input 散排；
2. **过滤区**（lib-filter）：库内筛选输入 + 状态**分段器**（seg：全部/已发
   现/已分析/…带计数）——状态从 chip 升级为分段控件，语义更明确；
3. **分组行**（lib-groups）：分组 chips 独立成行，悬停浮现重命名/删除。

配套细节：多选操作条从「又一条 toolbar」改为浮动高亮卡（lib-bulk）；空状
态从一行灰字升级为图标 + 主文案 + 副提示；表格数字列 tabular-nums 等宽、
状态徽章加软色底、选中行加左侧强调条；「加载更多」从伪 chip 改为真按钮。

## 4. CSS 策略：追加覆盖而非重写

全站样式只有一个 index.css，重写会波及助手页。策略：**保留全部既有选择
器，末尾追加 M17 区块靠级联覆盖**——`:root` 补 `color-scheme: dark`（原生
控件深色渲染）与 accent-soft/shadow token；统一 select/password 样式；主
按钮改渐变 + 阴影；chip/弹窗补过渡动画。新增类全部带 lib-/seg-/settings-
前缀，不与旧类冲突。实测助手页零回归。

## 5. 测试与验证

- `tests/test_api_settings.py` 7 个用例：覆盖层合并与优先级（Web Key 赢
  env）、损坏文件静默回退、脱敏格式、明文永不出现在 GET 响应、留空不清
  Key、测试连接的表单值/配置值取值优先级。沿用 test_api_agent 的
  monkeypatch 模式（假 load_config 指向 tmp_path，复用真实
  load_runtime_settings）；一个坑：delenv 要放在 client 构造**之后**
  （_client 内部会 setenv）。
- 真机链路：GET /settings 返回脱敏 Key ✓；弹窗内「测试连接」→ 智谱真实
  补全 →「连通正常（3156 ms，模型 glm-4.7）」✓；浏览器实测文献库三区布
  局、高级筛选网格、多选操作条、详情选中高亮、助手页回归 ✓。

## 6. 已知边界与后续

- settings.json 明文存 Key 于本机 data/——单用户本地工具的取舍（与 .env
  同级安全），多用户部署需引入密钥管理；
- embedding 端点暂未纳入设置页（当前硅基流动免费档够用，机制已支持，加
  一组字段即可）；
- 后续：检索预览弹窗按同一套视觉语言重做、亮色主题 token 化。
