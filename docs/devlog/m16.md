# M16 开发笔记 · Agent 模式上 Web

M14/M15 的 CLI agent loop 补上最后一层：**Web 界面与 REST API**。
助手页新增「对话 / Agent 任务」双模式，步骤轨迹实时可见，HITL 确认门在
浏览器里真正用了一次。

## 1. 服务层：agent_jobs（与通用 jobs 的分野）

M7 的 `jobs.py` 只有一个终态 result 字典，适合「跑完看结果」的流水线；
agent 循环要的是**过程可见**——每步工具调用边跑边产生事件。新增
`server/agent_jobs.py`：

- `AgentTaskState`：steps 列表随任务线程推进不断追加（`on_event` 回调
  `asdict(step)`），轮询端点每次返回全量步骤——单任务步数 ≤ max_steps，
  全量返回比做增量游标简单且够用；
- 每任务线程**独立打开账本连接与向量库**（沿用 `process_paper` 的线程
  模式），任务结束在 finally 里关闭；
- trace 继续落盘（`data/traces/web/<时间戳>.jsonl`），Web 触发的任务同样可复盘。

三个端点：`POST /api/agent/tasks`（202 返回 id）、
`GET /api/agent/tasks/{id}`（状态 + 步骤 + 用量）、
`POST /api/agent/tasks/{id}/confirm`（确认门决断）。

## 2. HITL 确认门：threading.Event 的等待-决断模式

M15 预装的 `confirm(count, titles) -> bool` 插座在 Web 里接的是真实交互：

- 任务线程的 confirm 回调把状态置 `waiting_confirm`、记下 `pending_confirm`，
  然后 `event.wait(timeout=300)` **阻塞任务线程**——LLM 循环停在 add_papers
  执行前，不烧 token；
- 前端轮询看到 waiting_confirm 弹确认框；`POST /confirm` 把决断写入
  `_Handle.declined`（拒绝时）并 `event.set()` 唤醒任务线程；
- 关键细节：Event 只能传「发生了什么」，传不了「结果是什么」——同意/拒绝
  用共享的 declined 标记区分；**超时按拒绝处理**（宁可少做不可多做），
  防止用户关页导致任务线程永久挂起。

## 3. 前端：轮询状态机与步骤时间线

- 助手页顶部「对话 / Agent 任务」双模式；Agent 模式隐藏会话侧栏
  （Agent 任务不入会话历史，是独立的一次性运行）；
- 提交后 1.2s 间隔轮询，done/error 停止并触发文献库刷新（任务可能入库了
  论文）；组件卸载清掉定时器防 setState 泄漏；
- 步骤时间线：序号 + 工具名（等宽字体）+ 参数（截断）+ 四态彩色徽章 +
  耗时 + 一句话详情；运行中显示 spinner 行；
- 确认框内联在时间线下方（非模态弹窗）：标题 + 论文清单 + 确认/拒绝；
- 结果面板 Markdown 渲染 + 「N 步 · X tokens」用量行；
  max_steps/token_budget 软着陆带黄色提示。

## 4. 踩坑与观察

- **IAB 浏览器 Playwright locator click 会挂起**（复现了此前记录的坑）：
  改 `cua.click({x, y})` 坐标点击 + 截图定位，一律绕开 locator click；
- 循环层默认 chat_fn 会带 `cfg` 关键字调用 `chat_with_tools`，测试假模型
  签名必须 `def fake_chat(messages, *, tools, **_)` 接住它；
- 真机验证链路：curl 提交→轮询（步骤 1ms 内可见，答案 ~20s）→ 浏览器
  UI 跑通「库状态 + 方向推荐」复合任务（2 步 / 2993 tokens），时间线与
  结果面板渲染符合设计。

## 5. 已知边界与后续

- Web 端 Agent 任务不做持久化：服务重启即丢（trace 文件仍在）；
  多任务并行会互相顶替面板显示（v1 单面板设计）；
- 确认等待上限 5 分钟，长任务批量入库要用户在场；
- 后续：任务历史列表、SSE 替代轮询、把对话模式的检索意图也升级为 agent 内核。
