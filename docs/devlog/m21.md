# M21 开发笔记 · 跨页状态保持 + 库页整列滚动

用户反馈两条：① 在助手页跑 Agent 任务，切到文献库再回来，任务页丢了；
② 文献库顶部固定的检索/过滤/分组区太长（约 280px），列表一滚动就占掉小
半屏，希望搜索区随内容一起滚走。

两条反馈指向同一类根因：**组件的生命周期与视口状态被错误绑定**。

## 1. 双页常驻挂载：切页不再卸载组件

原实现 `main` 里条件渲染 `{tab === "library" ? <Library/> : <Assistant/>}`，
切 tab 即卸载另一页——Agent 任务的 `agentTask`/轮询定时器、文献库的筛选
条件/滚动位置/检索预览全部随之销毁（后端 job 还在跑，只是 UI 看不见了）。

改为**两页常驻挂载、仅显隐切换**：

```tsx
<div className={`page ${tab === "library" ? "" : "off"}`}>
  <Library ... />
</div>
<div className={`page ${tab === "assistant" ? "" : "off"}`}>
  <Assistant active={tab === "assistant"} ... />
</div>
```

- `.page { flex:1; display:flex }` + `.page.off { display:none }`——布局
  行为与原来完全一致，但组件实例不销毁；
- 常驻挂载的副作用一并处理：`autoFocus` 只在首次挂载生效 → Assistant
  接收 `active` prop，切回时 `inputRef` 补焦点；
- 实测 Chromium 下 `display:none` 往返**不丢** `scrollTop`（420 → 420），
  列表滚动位置免费保留；
- 轮询定时器在隐藏期间照常跑，Agent 任务切走仍推进。

### 执行中小红点

任务在后台跑时用户在文献库页毫无感知——`Assistant` 用 `onAgentBusy`
上报 `agentBusy`，顶栏「助手」按钮上亮绿点（`@keyframes pulse` 呼吸
动画），任务结束（done/error）自动熄灭。waiting_confirm 期间
`agentBusy` 仍为 true，等确认也能看到。

## 2. 库页整列滚动：搜索区随内容滚走

原布局滚动容器是 `.table-wrap`，`.lib-head`（检索区）/`.lib-filter`/
`.lib-groups` 三个区在其外，永远钉住。修复 = 把滚动容器上移一层：

- `.list-pane` 加 `overflow-y: auto`，`.table-wrap` 改 `overflow: visible`；
- 向下滚时三个区随内容自然滚走，列表独占视口；
- 表头 `th` 的 `position: sticky; top: 0` 不用改——sticky 永远相对
  **最近的滚动祖先**，容器上移后自动变为相对 `.list-pane` 钉住（紧贴
  顶栏下沿），滚多远都有列名；
- 配套：`table.papers` 从 `border-collapse: collapse` 改
  `separate + border-spacing: 0`——collapse 下 sticky 表头的边框在
  Chromium 有长期渲染 bug（钉住时边框消失），separate 视觉等价且无此问题。

## 3. 验证

- 布局量测（evaluate）：`list-pane` overflowY=auto、scrollHeight 14628 >
  clientHeight 652；滚动 400px 后 `.lib-head` bottom = -229（完全滚出），
  `th.top = 58` 精准钉在顶栏下沿；
- Agent 任务真机闭环：提交「看看库状态」→ 立即切文献库（顶栏红点亮、
  agent-log 在隐藏页保持活跃）→ 切回助手：模式仍是 Agent 任务、任务行
  与步骤时间线原样保留、答案渲染完成、红点熄灭；
- 截图验收滚动中部版面：三区滚走、表头单行钉住、列表占满视口；
- 后端未动，回归 199 测试全绿（改动纯前端 `App.tsx`/`Assistant.tsx`/
  `index.css`）。

## 4. 面试视角

- **状态放哪里决定它活多久**：React 组件卸载 = state 销毁。跨页需要
  存活的状态，要么提升（lift up）/外置（store、URL、后端），要么让
  组件不卸载。本例选常驻挂载，因为要保活的不是一两个值而是「轮询中的
  定时器 + 全部交互状态」，整体保留比逐项搬运更简单可靠；
- **sticky 的相对性**：`position: sticky` 不是相对视口，是相对最近的
  滚动祖先——改滚动容器不用动 sticky 规则，理解这条就能免费迁移；
- **border-collapse: collapse 与 sticky th 不兼容**（Chromium 钉住时
  边框丢失），表格 sticky 表头的标准解法是 `separate + border-spacing: 0`。
