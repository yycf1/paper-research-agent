# M19 开发笔记 · 项目定位与复现执行器 MVP

用户的核心质疑：「普通的问答 AI 给它一篇论文也能达到这个效果，这个项目的
特色是什么？能做到普通 AI 做不到的什么？功能太简单单调，没体现 agent 范例。」
这个批评是对的，而且必须回答——项目名叫「文献阅读**复现** agent」，但复现链
只做到了 repro_plan.md（纸面方案）就停了。本里程碑做两件事：把定位讲清楚，
把最能体现 agent 范式的一环补上。

## 1. 定位：五件对话 AI 做不到的事

- **记忆**：本地文献库是持续累积的资产（账本 + 向量索引 + 知识产物），跨会话可用；
- **手**：接真实学术数据源检索/去重/下载真 PDF——不编造不存在的参考文献；
- **长时自主**：agent loop + 代码强制的护栏，无人值守多步任务可复盘；
- **可度量**：排序指标 + agent 评测集 + 评测-修复-复测闭环；
- **动手验证（M19 补齐）**：写代码 → 沙箱执行 → 读报错自纠错——对话 AI
  无法闭环的一环。

护城河本质：**对话 AI 只能读你贴给它的文本；这个系统拥有一份不断增长、
可检索、可执行、可度量的研究资产。**

## 2. 复现执行器 MVP：同一循环，新工具面

M14 的 agent loop + M15 的护栏是「底座」，M19 给它换上一层更锋利的工具面
（5 → 9 个工具），让模型自主走通「读方案 → 写代码 → 跑代码 → 修代码」：

- `read_repro_plan`：repro_plan.md + experiment.json 一起回填（方案缺失时
  fatal 带引导：先去详情页生成）；
- `write_code`：代码写进 `data/repro/<id>/workspace` 隔离工作区；文件名
  白名单（`Path(name).name != name` 拒绝路径穿越，仅 .py），单文件 30KB 上限；
- `run_code`：`subprocess.run([sys.executable, name], cwd=workspace)` 独立
  进程执行，5~180s 超时，stdout/stderr 各截断 3000 字符；
- **自纠错语义的关键决策**：代码崩溃 ≠ 工具失败——子进程正常跑完就返回
  ok，payload 里带非零 exit_code 与 stderr。循环层不会把它当错误重试，
  模型读到报错自己修代码重跑；超时同理（timed_out + 优化建议）。只有
  参数非法/文件不存在才是 fatal；
- **HITL 复用**：run_code 无条件过 M15 的 confirm 插座（count=1, titles=
  [文件名]）——「危险操作类工具复用同一确认门」的设计在 Web 端零改动生效。

沙箱边界如实声明：这是**进程级隔离 + 超时 + 文件白名单**，不是容器级沙箱；
单用户本地工具的合理取舍，多用户部署需要 Docker/订阅容器池。

## 3. compare_papers：护城河展示工具

跨论文对比的证据只能来自本库向量索引——普通 AI 没有这份数据。
`compare_papers(topic, paper_ids?, k_per_paper?)`：每篇论文各自 retrieve
（`paper_id` 过滤），返回分组证据（章节/页码/截断文本）；缺省取最近
processed 4 篇；system prompt 明确「综合对比前必须先收集证据，不要凭记忆」。

## 4. 评测集扩容与边界语义

- 新增 compare-01（指定两篇库内论文对比方法差异）、repro-01（写最小可运行
  原型并实际运行，must_call 三件套，max_steps 12——给自纠错留余量）；
- **边界用例的 forbidden 列表同步扩容**：boundary-code-01（"帮我写快排"）
  现在必须禁 write_code/run_code——工具变多后，边界判定的口径要跟着工具
  面长大，否则越界操作测不出来；
- repro-01 的前置：read_repro_plan 依赖 repro_plan.md 存在，评测跑前先对
  目标论文生成方案（eval 的公平性取决于任务前置条件，而不是模型能力）。

## 5. 评测实测（M19 扩容轮，12 任务真机）

- **完成率 / 工具合规率 / 答案命中率 100%，越界操作 0**；平均 2.5 步 /
  17538 tokens（较 M15 的 5240 上升：9 工具注册表让每步 system+schemas
  变大 + repro-01 本身 11 步重活——如实记录）；
- **repro-01 轨迹（本里程碑的招牌证据）**：`read_repro_plan → write_code →
  run_code → write_code → run_code → …` 共 11 步，5 写 5 跑交替自纠错，
  最终产物是 10KB 的 numpy 原型（合成 QA 数据 + 拓扑排序 + GCN + 图注意力，
  映射论文的 Knowledge→Graph→TopoSort→GCN→Attn 流水线），进化策略训练
  收敛到 100%，**并自主设计消融实验**：去掉 GCN 后跌到 25%（接近随机），
  用数据证明方法的关键模块真的起作用——这是「复现」从纸面方案走向
  可执行验证的一步；
- compare-01（5 步）：模型先用 compare_papers 收集两篇论文的分组证据，
  再用 ask_library 定向补查细节，最后综合——编排顺序与 system prompt
  的引导一致；
- boundary 扩容后全部 0 工具调用：工具面翻倍没有诱发越界。

## 6. 踩坑

- 多行 `python -c` 在本机 shell 静默失败（再次踩到）——轮询脚本落盘再跑；
- run_code 的超时测试用 `time.sleep(30)` + `timeout_sec=5`：下限 5s 是
  防止模型把超时设得过小导致正常代码总被杀；
- eval-agent 不带 `--trace` 不落轨迹——想复盘就带上它。
