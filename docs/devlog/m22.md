# M22 开发笔记 · MCP server：工具面协议化

用户拍板的下一步：先补提交（M14~M21 七笔落库），再做 M22——把 9 个工具经
MCP（Model Context Protocol）暴露出去，让 Claude Desktop / Cursor 等 host
直接调用这个文献库。

## 1. 为什么几乎零改造成本

M19 设计时留了伏笔：`TOOL_REGISTRY` 的每个条目就是 MCP 规范的
`description + inputSchema`。MCP server 因此不需要维护第二份 schema——
`list_tools` 直接遍历注册表，工具层以后加改，协议层自动跟进。执行侧同样
复用 `ToolExecutor`（与 CLI agent / Web 后台任务同一份），四态结果语义、
add_cap、文件名白名单、子进程超时等硬护栏原样生效。

协议适配层只有一件事可做：**决定护栏如何跨协议映射**。

## 2. 关键设计决策

- **HITL 确认插座的映射**：stdio 场景没有可弹确认框的前端。方案 =
  `PAPER_AGENT_CONFIRM=approve|reject` 环境变量决断 + stderr 审计日志。
  硬护栏（add_cap 直接拒绝）不随该开关变化——交互方式可以降级，护栏不能放宽。
  更完整的方案是 MCP 的 elicitation 机制（服务端向 host 请求用户输入），
  留作后续。
- **会话状态串行化**：`add_papers` 依赖「最近一次 search_papers 预览」，
  这是 executor 内的会话状态；MCP 请求可能并发到达，锁串行化 execute。
  踩过一个真坑：惰性初始化锁与会话锁用了同一把非重入 `threading.Lock`
  且嵌套获取——**自死锁**，首个工具调用永久挂起。修复 = 两段锁分离不嵌套。
- **同步执行器进线程池**：SQLite/HTTP/子进程都是阻塞调用，
  `anyio.to_thread.run_sync` 卸载，不卡 stdio 事件循环。
- **is_error 语义**：非 ok 状态（fatal/degraded/retryable_error）统一
  `is_error=true`，但 payload（JSON）完整回填——host 端模型能看到
  retry_after 与错误详情自纠错，与 agent loop 的错误回填哲学一致。

## 3. SDK 2.x 的 API 变化（踩坑记录）

官方 `mcp` SDK 2.2.0 与教程泛滥的 1.x 差异不小：

- 低层 `Server` 去掉了 `@server.list_tools()` 装饰器，改为构造参数
  `on_list_tools` / `on_call_tool` 回调；
- 模型字段 camelCase → snake_case：`inputSchema` → `input_schema`、
  `serverInfo` → `server_info`（InitializeResult）；
- `mcp.shared.memory.create_connected_server_and_client_session` 便捷助手
  被移除，测试要用 `create_client_server_memory_streams` 原语自己接
  ClientSession + Server.run。

## 4. 验证

- 协议测试（`tests/test_mcp_server.py`，5 用例，SDK 内存流 + 真实握手）：
  initialize 握手 + 9 工具按注册表顺序暴露、schema 均为 object；
  library_status 全链路 ok（tmp 库 seed 数据断言 total）；未知工具 →
  fatal + is_error；**错误回填语义跨协议保持**（无预览 add_papers →
  fatal，host 端模型可自纠错）；confirm 门环境变量三态。
- stdio 冒烟：以真实 host 的方式拉起 `pa mcp` 子进程，NDJSON JSON-RPC
  完成 initialize → tools/list → tools/call（library_status 返回库内
  335 篇），即 Claude Desktop 的接入路径。
- 全量回归 204 通过（199 + 5）。

## 5. 面试视角

- **单一事实来源**：schema 只在 TOOL_REGISTRY 维护，协议层是消费者不是
  复制者——工具演进不需要同步三处（CLI/Web/MCP），这是这次改造最重要的工程决策；
- **协议适配层的职责边界**：适配层不改语义、不放宽护栏，只回答「这个
  交互在本协议下怎么表达」（HITL → 环境变量 + 审计）；
- MCP 的价值叙事：从「一个带 Web 的工具」到「任何 agent host 可挂载的
  标准工具服务」，工具面写一次，三个入口（CLI/REST/MCP）共享。
