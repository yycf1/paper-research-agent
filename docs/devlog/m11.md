# M11/M12 开发笔记 · 真实使用一致性修复 + 复现规划器

夜间值守批次，两条主线：**M11 把真实使用暴露的不一致与静默失败清掉**；
**M12 开工二期复现链第一步（复现规划器）**。工作方式：先浏览器黑盒实测 +
回收并行闲时任务的实测情报，再按证据修。

## M11 · 一致性与静默失败（两批提交）

### 1. 空报告污染状态机（最重缺陷，实测发现）

- **现象**：库内 12 份 report.md 中 6 份只有 2 字符（换行），对应论文状态却是
  analyzed/indexed——详情页看不到精读报告，`pa analyze --all` 也扫不到它们。
- **根因**：`generate_report` 无空回复防护。GLM 混合推理模型的思考 tokens
  吃满 max_tokens 时返回空串（M9 已在问答链确认过该机制），空串被
  `strip_code_fence` 原样放行 → 写盘 → 状态推进。问答链早有 thinking=False
  重试兜底，报告链没有——**同一故障模式在两条链上只修了一条**。
- **修复**：
  1. `chat_markdown_safe` 公共兜底：空回复禁思考重问一次，仍空抛
     `EmptyReportError`（RuntimeError 子类）；报告/复现方案共用；
  2. 异常粒度分层：`EmptyReportError` 按单篇失败处理（状态保持 parsed 可
     重试、不中止整批），通用 RuntimeError（缺 Key）才中止阶段——
     **异常分类决定失败半径**；
  3. 存量修复路径：`run_analyze` / `pa analyze --all` 扫描 analyzed/indexed
     中 report.md 缺失或 <30 字符的论文，只重生成报告——experiment.json
     已存在时跳过提取（不重复付费），原状态保留（**indexed 不降级**，
     否则重试扫描又看不见）。
- **通用知识**：状态机语义完整性的教训（M6）只管住了「失败别推进」，没管
  「成功但产物为空」——**产物校验是状态推进的前置条件，不是可选步骤**。

### 2. CLI 检索与 Web 入库交互不一致（并行任务实测发现）

- **现象**：`pa search` 无条件把全部候选灌入库（一次 40 篇），与 M10 Web 端
  「机器找、人挑选」的设计矛盾；长期后果是 346/372 篇堆积在 discovered。
- **修复**：`pa search` 默认预览不写库（带行号表格 + 重复标注）；
  `--ingest` 全收保留旧行为；`--pick 1,3-5` 按行号选收；`--tag` 自定义分组。
  chat 助手的全自动检索不变（对话场景选文交还给流水线预筛）。
- **配套**：`pa prune --status/--tag [--yes]` 批量全链删除，治理历史堆积；
  涉及 parsed/analyzed/indexed 时额外警示。
- **通用知识**：交互模式升级时，旧入口不升级就是「两套产品」——一致性不是
  视觉问题，是数据流问题。

### 3. Web 打磨（实测 + 代码走查发现）

- **跨源重复候选**：同一论文（同 DOI/同题/不同 sid）在预览里出现两次，
  一次「新候选」一次「库内已有」——按代表 id 去重，只渲染一次；
- **一键处理静默失败**：进度区被 `processing &&` 包住，job 结束后失败步骤
  （如「无 OA 全文」）不可见。改为结束后保持可见 + 最终状态行；
- **差异化产物未展示**：experiment.json 的 repro_assets（代码/数据集链接）、
  reproducibility_notes、unverified_claims 前端完全没渲染——这恰是项目的
  差异化卖点。实验结构视图补齐三块内容 + 逐字段置信度三色徽章；
- **轻量 Markdown 渲染器**（零依赖 `md.tsx`）：精读报告/全文/对话回复此前
  按 pre-wrap 纯文本展示，`##`/`**` 原样暴露；解析产物里的 `<!-- p.1 -->`
  分页注释也直接漏给用户。渲染器覆盖标题/列表/代码块/行内样式/链接，
  丢弃 HTML 注释行；
- 杂项：库内筛选 300ms 防抖、入库后列表必刷新（setTag 同值不触发重渲染
  的边界）、「未分组 N」入口（untagged 统计 + 过滤）、「加载更多」分页
  （200 条截断从静默变为可控）、详情页状态中文化、上传临时子目录防同名
  互覆、job 失败后刷新论文 error 字段、删除确认的省略号只在真截断时出现。

### 4. qa 出处贯通

chat 问答链的回答带 `[1][2]` 编号却无出处对照（CSS 里 `.sources` 一直
存在但没用上——M8 改版时丢的）。修复：`AssistantReply.sources` →
`/api/chat` 响应 → chatstore 新列持久化（老库 PRAGMA 自动迁移）→ 前端
渲染可点击出处（跳详情页），历史消息同样恢复。**「对话里的编号必须有
对照」是 RAG 可信度的底线，不是装饰。**

## M12 · 复现规划器（二期复现链第一步）

- 严格按 PLAN §4 硬约束：输入收敛到 **experiment.json + 复现资产链接**
  （论文节选仅补细节）；experiment.json 不存在时明确报错而不是降级瞎编。
- 产出 `data/knowledge/{sid}/repro_plan.md`，六节结构：复现目标 / 复现资产
  评估 / 环境搭建 / 实施步骤 / 预期指标与比对 / 风险与缺口。prompt 明确
  「未验证声明不当作论文事实引用」。
- **不改动五态状态机**：复现方案是增量产物而非流程阶段——状态机语义已
  在 M6 收敛过一次，不再为新产物加状态。
- 入口：CLI `pa plan <id> [--force]`、API `POST /papers/{sid}/plan`、
  Web 详情页「复现方案」页签 + 「生成/重新规划」按钮（无 experiment 时
  禁用并说明原因）。
