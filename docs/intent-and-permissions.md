# 意图识别、模型配置与权限

2026-10-16 根据实际连续对话反馈修复。模型配置按 `config.yaml → .env 密钥 → data/settings.json 的文本端点覆盖` 合并，Web 保存后后续请求读取最新配置。文本端点、模型和 Key 不会自动替换向量化与重排序配置。

本次实际配置与真实响应均为阿里云百炼 `qwen3.7-flash-2026-07-15`。向量化仍是硅基流动 BGE-M3，重排序仍是 BGE Reranker v2 M3。正文与题录会按具体功能提供给相应模型服务，API Key 由程序用于请求认证，不作为提示词发送。

## 统一研究对话的处理

| 入口 | 意图处理 | 执行范围 |
| --- | --- | --- |
| 提问与追问 | 高置信规则 → 大模型 JSON 分类 → Python 分发；分类与问答接收当前资料范围内最近三轮语境 | 默认全库，也可选择 1–6 篇；只读，范围随对话保存 |
| 比较论文 | 显式比较指令直接进入逐论文证据比较，结果与候选字段保存进当前会话 | 选择 2–6 篇；可在同一对话继续追问，不自动写库 |
| 执行操作 | 显式提交后，模型通过 Function Calling 选择工具、多轮推进；使用同范围最近语境理解指代 | 执行器约束白名单、论文范围和确认门；历史语境不授权旧操作 |

连续对话是规则与大模型结合的路由，没有额外训练的意图分类网络，也不是让模型直接控制数据库。分类失败会记录错误类型、提示降级并采用保守规则。退出和帮助指令须完整匹配，不把 Query/SQL 中的 q 或“论文怎么用某方法”误识别为命令。

分类包含 search、qa、catalogue、status、explore、off_topic、clarify、exit、help。`catalogue` 再分为方向概览、按方向计数、列出匹配题录和方法概览。只返回“全库多少篇”的 status 不能用于回答方向数量。

## 用户反馈对应的修复

| 输入 | 原处理问题 | 当前处理 |
| --- | --- | --- |
| 当前库中的论文都是哪些研究方向上的？ | 被当作全库状态，只返回状态计数 | 按题录标题归纳方向，标明标题覆盖数量和未做全文分类 |
| Rag方向上有多少篇论文？ | 没有筛选逻辑，返回全库总数 | 程序匹配标题、摘要、分组中的明确关键词及已定义同义词后计数 |
| 你是谁 | 通用帮助模板，没有身份说明 | 回答个人文献研究助手身份、当前配置模型和可执行的只读功能 |
| 解释库中论文所使用的方法 | 一条宽泛问题检索少量片段，相关性不足 | 先从最多四篇已索引论文分别取方法章节，缺少明确章节时逐篇检索，再带来源概括 |

方向数量通过 RAG / retrieval augmented generation / 检索增强生成等同义词匹配计算，并单独报告已索引数量。这是题录匹配口径，不能当作全文相关论文的完整数量。方向概览报告实际覆盖的标题数量，是模型初步归纳，不是人工审定分类。方法功能不会把未索引全文纳入结论；每次最多四篇、每篇两块，不能称为全部论文的完整方法分析。

## 权限由程序持有

- 普通提问、追问和比较没有自动入库、删除、下载、代码写入或执行权限。模型返回 search 分类也不会绕过 Web 的 `allow_ingest=False`。选择“执行操作”仍需点击“提交执行”，切换选项和预填内容不会执行。
- Agent 使用注册工具白名单。宿主指定 `allowed_paper_ids` 或锚定论文后，模型参数只能缩小范围；检索/入库/推荐工具在该范围下隐藏，并在执行器再次拒绝越界调用。
- 入库单次上限20篇；Web 达到5篇时需要确认。运行代码在 Web 中需要确认，拒绝后不执行。评测或直接调用执行器未提供确认回调时，会自动放行，因此不能把这个确认机制描述成所有调用方式都强制授权。
- 原型文件接口限制到论文工作区的 Python 文件，并限制大小和运行超时。不过代码执行没有操作系统沙箱，生成的 Python 程序仍具有本地进程权限。工具路径约束不等于运行时隔离。
- 当前是本机单用户应用，没有多用户登录、角色授权或公网访问控制。网页的手动删除、上传和设置接口与模型工具不是同一层权限。

普通问答只能依据程序提供的题录、检索片段和最近会话作答；它不会自动读完所有 PDF。没有索引、来源过期或引用结构失败时必须解释限制。一般概念问题目前仍主要沿文献问答链处理，尚未实现独立的通用知识聊天模式。

## 验证与代码入口

完整 Python 回归427项通过，前端 build/lint 通过，保留三条原有 effect 警告。新增15项回归覆盖用户四个例子、错误规则、历史传递、方向匹配计数、作用域、千问思考参数和逐篇方法来源。

真实千问请求验证了配置和题录方向概览；RAG计数只读实际 SQLite，没有生成模型数字。方法解释另用原创隔离资料、真实 SQLite/Chroma 与千问验证两篇来源。没有写入个人文献记录，没有为获得更好答案改写原始模型结果。

实现入口：`graph/route.py`（分类）→ `services/assistant.py`（分发与只读控制）→ `services/catalogue.py`（题录统计及方法概览）；`server/routes.py` 定义入口，`agent/scope.py` 与 `agent/executor.py` 强制 Agent 范围和工具限制。
